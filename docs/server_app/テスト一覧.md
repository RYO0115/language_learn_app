# server_app テスト一覧

最終更新: 2026-06-24 / バージョン: 0.4.1

## 概要

`server_app` のテストは2種類ある。

- **UI 回帰テスト**（`tests/ui/`）: Playwright for Python（`pytest-playwright`）でブラウザを操作し、
  ページ・フローを検証する
- **ユニットテスト**（`tests/unit/`）: in-memory SQLite を使い、ブラウザ・サーバー起動を介さず
  サービス層の関数を直接検証する。出題優先度のような、ブラウザ越しでは決定的な検証が難しいロジックに用いる

いずれも `.github/workflows/server_app_test.yml` により `server_app/**` への変更時（push・PR）に
GitHub Actions 上で自動実行される。

npm は使用せず、`uv`（pip 経由）で Playwright 本体・ブラウザバイナリを取得する。

## 実行方法

```bash
cd server_app
uv sync
uv run playwright install --with-deps chromium
uv run pytest tests/unit tests/ui -v
```

## テスト基盤

| ファイル | 役割 |
|---------|------|
| `tests/ui/conftest.py` | `live_server` / `rate_limited_server` フィクスチャ。uvicorn をサブプロセスで起動し、テスト用一時 SQLite DB・`AI_PROVIDER=stub` で動かす |
| `tests/ui/helpers.py` | `unique_word()`（一意な単語名生成）、`add_word_via_ai_stub()`（AI生成→保存の共通ヘルパー） |
| `tests/unit/conftest.py` | `db` フィクスチャ。in-memory SQLite（`sqlite:///:memory:`）にテーブルを作成したセッションを返す |

- DB はテストセッション内で共有されるため、各テストは `unique_word()` で生成した一意な単語名を使い、テスト間の干渉を避けている。
- AI 呼び出しは `StubProvider`（`features/ai/providers/stub.py`）が固定データを返すため、実 API キー・コストなしに決定的に検証できる。`AI_STUB_FORCE_RATE_LIMIT=1` を設定した `rate_limited_server` ではレート制限（429）シナリオを再現する。

## テストケース一覧

### `test_dashboard.py` — ダッシュボード

| テスト | 検証内容 |
|--------|---------|
| `test_dashboard_loads` | `/` が表示され、登録単語数・連続学習日数・累計学習日数のセクションが存在する |
| `test_dashboard_links_to_add_and_quiz` | 「単語を追加する」「テストを開始する」リンクが表示される |

### `test_words.py` — 単語管理

| テスト | 検証内容 |
|--------|---------|
| `test_add_word_page_loads` | `/words/add` の表示、単語入力欄・AI生成ボタンの存在 |
| `test_add_word_via_ai_stub_appears_in_list` | AI生成（stub）→保存した単語が `/words` 一覧に表示される |
| `test_duplicate_word_detection` | 既存単語と同じ単語を入力すると重複メッセージが表示される（`/api/spell-check`） |
| `test_word_detail_edit_and_delete` | 単語詳細→編集（意味の更新が反映される）→削除（確認ポップアップ許諾後に一覧から消える） |

### `test_ai_generate.py` — AI生成ボタンの挙動（レート制限対応の回帰テスト）

| テスト | 検証内容 |
|--------|---------|
| `test_ai_generate_fills_form_with_stub_data` | 「AI で生成」クリックで stub のダミーデータがフォームに反映される |
| `test_ai_generate_button_disabled_during_request_and_cooldown` | クリック直後にボタンが無効化され、クールダウン秒数の半分経過時点でも無効化が維持され、15秒後に再有効化される |
| `test_ai_generate_confirm_popup_when_content_already_generated` | 生成済み内容がある状態で再クリックすると `window.confirm` ポップアップが表示される |
| `test_ai_generate_rate_limit_shows_retry_message` | レート制限（429）時にエラーパーシャルと再試行秒数のメッセージが実際に表示される（`rate_limited_server` 使用） |

> `test_ai_generate_rate_limit_shows_retry_message` は実装時に、htmx がデフォルトで 2xx 以外のレスポンスをスワップしない問題（429/500 のエラーパーシャルが画面に表示されない不具合）を検出した。詳細は `設計書.md` の「AI プロバイダ設計」を参照。

| テスト | 検証内容 |

| `test_stale_high_accuracy_word_resurfaces_over_recently_tested_low_accuracy_word` | 正答率100%でも長期間出題されていない単語が、直近に出題された低正答率の単語より優先スロットで選ばれる（未出題期間ベースの再出題ロジック） |

### `tests/unit/test_word_similarity.py` — 類似単語の事前計算ロジック（ユニットテスト）

| テスト | 検証内容 |
|--------|---------|
| `test_no_similarities_with_fewer_than_two_words` | 同じ品詞の単語が1件のみの場合は類似単語が登録されない |
| `test_similarities_created_for_same_part_of_speech_group` | 同じ品詞の単語2件が相互に類似単語として登録される |
| `test_different_part_of_speech_words_are_not_linked` | 異なる品詞の単語同士は類似単語として登録されない |
| `test_similarity_count_capped_at_top_n` | 類似単語の登録件数が `SIMILARITY_TOP_N`（5件）で上限となる |
| `test_update_word_part_of_speech_refreshes_both_groups` | 単語の品詞を変更すると、旧グループ・新グループ両方の類似単語が再計算される |
| `test_delete_word_cleans_up_and_refreshes_remaining_group` | 単語削除時に関連する類似単語レコードが削除され、残りグループが再計算される |
| `test_recompute_is_idempotent_delete_then_insert` | 同じ品詞グループに対して再計算を複数回実行しても結果件数が変わらない（delete + insert の冪等性） |
| `test_meaning_overlap_demotes_similarity_rank` | 綴りが似ていても意味がほぼ同じ（類義語）候補は、綴りが似ていて意味も異なる候補より類似度の順位が低くなる |

### `tests/unit/test_quiz_fill_blank.py` — 穴埋め3択テストのアンロック判定・選択肢生成・穴埋め化（ユニットテスト）

| テスト | 検証内容 |

| `test_not_unlocked_with_no_words` | 単語が0件の場合はアンロックされない |
| `test_not_unlocked_with_only_two_same_part_of_speech_words` | 同じ品詞の単語が2件のみ（誤答候補1件）ではアンロックされない |
| `test_unlocked_with_three_same_part_of_speech_words` | 同じ品詞・例文付きの単語が3件登録されるとアンロックされ、出題対象に全件含まれる |

## テスト追加時のルール

新しい機能追加・修正を行った場合は、`CLAUDE.md` の「server_app 開発ワークフロー」に従い、
対応するテスト（ブラウザ越しの検証が適切なら `tests/ui/`、サービス層のロジック単体を
決定的に検証したいなら `tests/unit/`）を追加・更新し、このファイル（テスト一覧.md）の
該当セクションも追記すること。
