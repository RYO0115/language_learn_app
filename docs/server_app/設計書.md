# server_app 設計書

最終更新: 2026-06-27 / バージョン: 0.4.3

## 概要

日本語話者向け英語学習アプリのバックエンドサーバー。
FastAPI + SQLite + Jinja2 によるサーバーサイドレンダリング構成。

### テスト構成

```
server_app/tests/
├── ui/
│   ├── conftest.py  # live_server / rate_limited_server フィクスチャ（uvicorn をサブプロセス起動）
│   ├── helpers.py    # 単語追加などの共通ヘルパー
│   └── test_*.py     # ページ・フロー別のブラウザ駆動テスト（Playwright + pytest-playwright）
└── unit/
    └── test_*.py     # サービス層ロジックの in-memory SQLite ユニットテスト
```

UI テストは `AI_PROVIDER=stub`・専用一時 SQLite DB で起動したサーバーに対して Chromium を操作する。DB はテストセッション内で共有されるため、各テストは一意な単語名を使い干渉を避ける。

ユニットテストは独立した in-memory SQLite（`create_engine("sqlite:///:memory:")`）を使い、サーバー起動やブラウザを介さずサービス層の関数を直接呼び出して検証する。出題優先度のような、ブラウザ越しに決定的な検証が難しいロジックに用いる。

### 静的解析（lint）

ruff を `[tool.ruff]` / `[tool.ruff.lint]`（`server_app/pyproject.toml`）で設定し、`uv run ruff check .` で実行する。
`.github/workflows/server_app_lint.yml` が `server_app/**` の変更時に自動実行し、main ブランチへのマージにはこのチェックの成功が必須（ブランチ保護で required status check に設定）。

SQLAlchemy のクエリ条件式（`Column == True/False`）は ruff の E712 で警告されるため、`.is_(True)` / `.is_(False)` を使う。
`Mapped["Word"]` のような文字列フォワード参照（循環インポート回避）は ruff が未定義名として誤検知するため `# noqa: F821` を付与する。

### 各 feature モジュールの構成

```
features/<name>/
├── models.py    # SQLAlchemy モデル
├── schemas.py   # Pydantic スキーマ
├── router.py    # FastAPI エンドポイント
└── service.py   # ビジネスロジック
```

### words テーブル

| カラム | 型 | 制約 |
|--------|----|------|
| id | INTEGER | PK, AUTO |
| word | VARCHAR(100) | UNIQUE, INDEX, NOT NULL |
| reading | VARCHAR(200) | NULL |
| meaning | TEXT | NOT NULL |
| part_of_speech | VARCHAR(50) | NULL |
| created_at | DATETIME | NOT NULL (UTC) |
| updated_at | DATETIME | NOT NULL (UTC) |

`word` カラムは保存前に `features/words/service.py` の `normalize_word_text()` で正規化される。
正規化内容は (1) 前後の空白除去、(2) 連続空白の単一空白への畳み込み、(3) ゼロ幅／不可視文字
（ZERO WIDTH SPACE `U+200B`・BOM `U+FEFF`・WORD JOINER `U+2060`・SOFT HYPHEN `U+00AD` など）の除去。
`str.strip()` ではゼロ幅文字を除去できず、iPhone のキーボードが末尾に付与するこれらの文字によって
「見た目が同じ単語」が別単語として重複登録されたり検索が 0 件になる問題があったため導入した。
登録（`create_word`）・テキスト照合（`get_word_by_text`）・一覧検索（`list_words`）・
インポート（`features/export/service.py`）・スペル/重複チェック（`POST /api/spell-check`）の
全経路でこの関数を通す。対象の文字集合は Unicode の制御・書式文字（技術的に閉じた集合）であり、
ユーザーの語彙内容を限定するものではない。

## AI プロバイダ設計

プロバイダは `BaseAIProvider` 抽象クラスで統一インターフェースを実装。

```python
class BaseAIProvider:
    def generate_word_info(self, word: str) -> AIGenerateResponse: ...
```

| プロバイダ | クラス | モデル | 出力方式 |
|-----------|--------|--------|---------|
| Claude | `ClaudeProvider` | claude-haiku-4-5-20251001 | JSON テキスト解析 |
| Gemini | `GeminiProvider` | gemini-2.0-flash | response_schema 構造化出力 |
| Stub（テスト専用） | `StubProvider` | なし（実 API 呼び出しなし） | 固定の `AIGenerateResponse` を即時返却。`AI_STUB_FORCE_RATE_LIMIT=1` で `AIRateLimitError` を強制発生 |

### エラーハンドリング

| 例外クラス | 用途 |
|-----------|------|
| `AIServiceError` | API 呼び出し失敗・レスポンス解析失敗時の基底例外。HTTP 500 を返す |
| `AIRateLimitError` | `AIServiceError` のサブクラス。クォータ超過・レート制限（429）時に送出し、`retry_after_seconds` に再試行までの待機秒数を保持する。HTTP 429 を返す |

各プロバイダは API クライアントが返すレート制限エラー（Gemini: `google.genai.errors.APIError` で `code == 429`、Claude: `anthropic.RateLimitError`）を捕捉し、レスポンスから再試行待機秒数を抽出して `AIRateLimitError` に変換する。

> **注意（htmx のスワップ挙動）**: htmx はデフォルトで 2xx 以外のレスポンスをスワップしない。
> `/api/ai/generate` が 429/500 を返す際にエラーパーシャルを表示するため、
> `words/add.html` で `htmx:beforeSwap` をハンドリングし、`#ai-fields` への
> レスポンスに限り `shouldSwap = true` / `isError = false` を強制している
> （UI テスト追加時に発見・修正）。

## クイズ優先度選択アルゴリズム（`select_quiz_words`）

1. **Tier 1**: 未テスト単語（`quiz_answers` に記録なし）→ ランダム順
2. **Tier 2（未出題期間優先スロット）**: Tier 1 で埋まらなかった残りスロットのうち、
   `STALE_WORD_QUOTA_RATIO`（0.1 = 10%、最低1件）分は、正答率に関わらず
   `MAX(quiz_answers.answered_at)` が最も古い（最後に出題してから最も時間が経過している）
   テスト済み単語を優先的に採用する。正答率が高い単語でも定期的に再出題されるようにするための仕組み。
3. **Tier 3**: 残りのテスト済み単語のうち正解率が低い順（`correct / total` 昇順）
4. **Tier 4**: それ以外の残り単語 → ランダム順

設定数（`QUIZ_QUESTION_COUNT`、デフォルト20）に達するまで各 Tier から取得し、最後に出題順をシャッフルする。

ユニットテスト: `server_app/tests/unit/test_quiz_priority.py`（in-memory SQLite で `select_quiz_words` を直接検証）。

`select_quiz_words` は `eligible_word_ids: set[int] | None` 引数で出題対象プールを絞り込めるため、
穴埋め3択テストのように出題可能な単語が限られるクイズタイプでも同じ優先度ロジックを再利用できる。

## 例文穴埋め3択テスト（`quiz_type == "fill_blank"`）

意味確認テストと並ぶ第2のクイズタイプ。単語の例文中の対象単語を空欄にし、似ている単語2件を含む3択から正解を選ぶ。

### アンロック条件（`is_fill_blank_unlocked` / `get_fill_blank_eligible_word_ids`）

以下をすべて満たす単語が1件以上存在する場合にアンロックされる。

1. `part_of_speech` が設定済み
2. 例文が1件以上ある
3. `word_similarities` に類似単語候補が2件以上ある（誤答選択肢2件を確保できる）

### 類似単語の事前計算（`features/quiz/similarity_service.py`）

`recompute_similarities_for_part_of_speech(db, part_of_speech)` が、同じ `part_of_speech`
（リテラル一致。複数品詞を `・` で連結した値はグループが分かれる）を持つ単語同士の類似度を計算し、
`word_similarities` に上位 `SIMILARITY_TOP_N`（5件）を保存し直す（delete + insert）。

類似度スコア = 先頭文字列の共通プレフィックス長 − 単語長の差 × 0.1 − 意味の重複度（meaning の文字
バイグラム Jaccard 類似度、0.0〜1.0）× 10（値が大きいほど似ている）。綴りが似ていても意味がほぼ同じ
（類義語）候補は、誤答選択肢として不適切になりやすい（例文中でどちらを入れても意味が通ってしまい、
正誤の判断材料にならない）ため、意味の重複度が高いほどスコアを大きく下げて順位を下げる。

このバッチ計算は `features/words/service.py` の `create_word` / `update_word`（品詞変更時は新旧両方の
グループ）/ `delete_word` / `bulk_delete_words` のたびに、関係する品詞グループのみ呼び出される。
出題時は事前計算済みの `word_similarities` からランダムに2件抜き出すだけで済むため、
出題ごとに類似度を再計算する必要がなく、単語数が増えても出題時の処理コストは増えない。

SQLite では FK の `ON DELETE CASCADE` を強制有効化していないため、`delete_word` /
`bulk_delete_words` では削除対象単語に関連する `word_similarities` 行を明示的に削除してから
単語本体を削除している。

### 出題データの構成（`start_quiz(quiz_type="fill_blank")`）

`select_quiz_words` で選んだ各単語ごとに、`_build_fill_blank_question` が以下を `QuizSessionWord` /
`QuizSessionWordChoice` として保存する。

1. 単語の例文からランダムに1件選び `QuizSessionWord.example_sentence_id` に設定
2. `word_similarities` から誤答候補2件をランダムに抽出し、正解（単語自身）と合わせて3件の
   `QuizSessionWordChoice`（順序はシャッフル済み）を作成

出題画面（`get_fill_blank_question_data`）では、例文中の対象単語を正規表現（単語境界・大文字小文字無視）で
`_____` に置換する。原形に加えて、`lemminflect`（形態素解析ライブラリ）の辞書ベースの活用形生成
（`_inflected_forms`）により、複数形・三単現・過去形・進行形・比較変化などの活用形候補もマッチ対象とする
ため、過去形・複数形・不規則変化（go → went、child → children、good → better など）に変化していても
空欄化できる。`Word.part_of_speech`（動詞/名詞/形容詞/副詞）を lemminflect の品詞タグにマッピングして
精度を上げ、品詞が未設定・対応表にない場合は品詞を限定せずに検索する。lemminflect の辞書にない語
（造語・専門用語等）は、OOV 用 API によるルールベース推定で補う。生成した候補のうち例文中で
最長一致する形が優先される。

回答（`submit_fill_blank_answer`）は選択された `word_id` と正解選択肢を比較して判定し、
`QuizAnswer` に記録した上で、例文の日本語訳と各選択肢の単語の意味（フィードバック用）を返す。

ユニットテスト: `tests/unit/test_word_similarity.py`（類似度計算・CRUD連携）、
`tests/unit/test_quiz_fill_blank.py`（アンロック判定・選択肢生成）。
UIテスト: `tests/ui/test_fill_blank_quiz_flow.py`。

## マイグレーション

`main.py` 起動時に自動実行:
- `example_sentences.label` カラムが存在しない場合に `ALTER TABLE` で追加
- `quiz_session_words.quiz_type` / `quiz_session_words.example_sentence_id` カラムが
  存在しない場合に `ALTER TABLE` で追加
- 単語が1件以上登録済みで `word_similarities` が空（旧フォーマット DB）の場合、
  全品詞について `recompute_all_similarities` を実行し類似単語候補を初期投入する
