# 穴埋め3択テスト 活用形ハードコード調査報告書

作成日: 2026-06-24 / 実装完了日: 2026-06-25 / バージョン: 0.4.2

> 本資料は調査・改善検討の記録（過去資料）。実装済みの最新仕様は
> `docs/server_app/設計書.md`「出題データの構成」節・`docs/server_app/機能一覧.md` Q-8 を参照。

## 背景

`作成したい機能一覧.md` に挙がった以下の指摘を調査した。

> 穴埋め3択テスト: 拡張性に乏しいハードコードが多く存在しているように見える。
> 活用形テーブルなどで単語のリストを用意するのは、自分で自分の単語帳を作るという
> このアプリのコンセプトに反しているので、まずは問題となる箇所のリストアップを行い、
> 改善案を検討してほしい。

## 調査結果（該当箇所）

### 1. `_IRREGULAR_VERB_FORMS`（該当・要改善）

- 場所: `server_app/src/language_learn/features/quiz/service.py:321-377`
- 内容: be / have / do / go / get / make … 約55個の不規則動詞とその活用形（三単現・過去形・過去分詞・進行形）を直接書き並べた辞書。
- 利用箇所: `_blank_word_in_sentence()`（同ファイル407行目）が、例文中で穴埋め対象の単語を検出する際にこのテーブルを参照する。
- 問題点:
  - ユーザーが単語帳に登録した不規則動詞が、このリストに**含まれていなければ活用形を認識できない**。原形・規則変化のみで一致を試みるため、例文中で活用形（例: "went"）が使われていると穴埋め箇所を検出できず、未加工の例文がそのまま表示される。
  - 新しい不規則動詞をサポートするには毎回コード変更が必要。「自分の単語帳を自由に作る」という本アプリの設計思想と矛盾する。
  - 不規則名詞（child→children、mouse→mice 等）や不規則形容詞の比較変化には一切対応していない（そもそもテーブルが動詞限定）。
  - 英語専用のテーブルであり、再利用性・拡張性が低い。

### 2. `_regular_inflections()`（該当しない）

- 場所: 同ファイル380-404行目
- 内容: 複数形・三単現・過去形・進行形などを文字列処理のルールで都度生成するアルゴリズム。固定の単語リストではなく、入力単語から動的に生成するため、コンセプトには反していない。
- 補足: ルールベースのため、不規則変化（上記1）や一部の例外（例: "y" で終わる単語の特殊形など）を完全にはカバーできていないが、これは「ハードコードされた単語リスト」の問題ではなく「アルゴリズムの精度」の問題。

### 3. `WordSimilarity`（誤答選択肢候補）（該当しない）

- 場所: `similarity_service.py`
- 内容: ユーザーが登録した単語同士の類似度を都度計算し保存。固定の単語リストは存在しない。

### 4. `get_fill_blank_eligible_word_ids`（出題可否判定）（該当しない）

- DB クエリのみで構成されており、固定リストはない。

## 結論

ハードコードされた単語リストが「自分の単語帳を作る」コンセプトに反する形で存在するのは **`_IRREGULAR_VERB_FORMS` の1箇所のみ**。

## 改善案（採用）: 形態素解析ライブラリの導入

[`lemminflect`](https://github.com/bjascob/LemmInflect) を導入し、`_IRREGULAR_VERB_FORMS` を完全に置き換える。

### 概要

- lemminflect は単語の原形（lemma）と品詞タグを渡すと、辞書ベースで活用形を返すオフラインライブラリ（spaCy 等の依存なしでも単体動作可能）。
- ネットワーク呼び出し不要・無料・決定的な結果を返すため、出題のたびに呼び出してもコスト・レイテンシの問題がない。
- 動詞だけでなく名詞の不規則複数形（child→children）、形容詞の不規則比較変化（good→better/best）もカバーできるため、現状の `_IRREGULAR_VERB_FORMS`（動詞限定）より対応範囲が広がる。

### 実装方針

1. `pyproject.toml` に `lemminflect` を依存追加する。
2. `_IRREGULAR_VERB_FORMS` 辞書を削除し、`_blank_word_in_sentence()` 内の活用形候補生成を lemminflect の `getAllInflections()` 呼び出しに置き換える。
3. `Word.part_of_speech`（日本語ラベル: 「動詞」「名詞」「形容詞」等）を lemminflect の universal POS タグ（`VERB` / `NOUN` / `ADJ` / `ADV`）にマッピングする小さな対応表を用意する。品詞が未設定・マッピング対象外の場合は全タグを横断的に検索するフォールバックとする。
4. `_regular_inflections()` は、lemminflect が辞書にない未知語（造語・固有名詞等）に対するフォールバックとして残す（lemminflect は未知語に対しては空またはルールベース結果を返すため、念のため併用する）。

### 影響範囲・リスク

- 依存追加（軽量、辞書データはパッケージに同梱されるためモデルダウンロード等は不要）。
- `tests/unit/test_quiz_fill_blank.py` の不規則動詞関連テストケースの一部修正が必要（ハードコード辞書への直接参照がある場合）。
- 既存の挙動（不規則動詞の穴埋め）は維持されつつ、対応範囲が拡張される（名詞・形容詞の不規則変化にも対応）。

## 実装結果（2026-06-25 完了）

上記方針どおりに実装した。差分は以下の通り。

- `pyproject.toml` に `lemminflect` を依存追加。
- `quiz/service.py` の `_IRREGULAR_VERB_FORMS` を削除し、`_inflected_forms()`（lemminflect 呼び出し + OOV フォールバック）に置き換え。`_regular_inflections()` は撤去（lemminflect の OOV API がルールベース生成を兼ねるため不要）。
- `_blank_word_in_sentence()` に `part_of_speech` 引数を追加し、`get_fill_blank_question_data()` から `Word.part_of_speech` を渡すよう変更。
- `tests/unit/test_quiz_fill_blank.py` に不規則名詞（child→children）・不規則形容詞比較変化（good→better）の新規テストを追加。既存テストは変更なしで通過。
- `docs/server_app/設計書.md`・`機能一覧.md`・`テスト一覧.md` を更新し、`v0.4.2` にバージョンアップ。

### 未採用案: AI生成による活用形保存

単語登録時に AI（既存の `features/ai` 連携）へ活用形も生成させ、DB に保存する方式も検討したが、以下の理由で見送る。

- 単語登録のたびに追加の AI 呼び出しコストが発生する。
- lemminflect で十分カバーできる範囲（英語の活用形生成）に対して、AI 呼び出しは過剰投資。
- 将来的に AI が生成する例文の文体・語形に対する追従性は AI 案に利点があるが、現時点では優先度が低い。
